# Cloux Messenger

Вебзастосунок Cloux і файли клієнтів. Для production увімкніть постійну базу даних: локальний SQLite потрібен лише для розробки й тестів.

## Постійне сховище на Render Free

Render Free має тимчасову файлову систему. Cloux підтримує віддалену SQLite-сумісну базу Turso, а також зберігає вкладення, аватари, банери й шпалери всередині бази.

1. Створи безкоштовну базу Turso та збережи її URL і токен.
2. У Render → сервіс `cloux-messenger` → Environment додай:
   - `TURSO_DATABASE_URL` — URL Turso.
   - `TURSO_AUTH_TOKEN` — токен Turso як секрет.
   - `CLOUX_REQUIRE_DURABLE_STORAGE` — `true`.
3. Збережи змінні через **Save only** — цей крок не перезапустить чинний контейнер.
4. Деплой код із підтримкою Turso. Після цього Render Free запускатиме Cloux лише з віддаленою базою.

На Render застосунок не стартує без обох секретів. Перевір `/api/health`: `persistent_storage` має бути `true`, а `storage_backend` — `turso`.

### Важливо перед першим деплоєм

Цей код не може перенести базу зі старого Render Free автоматично. Стара SQLite-база лежить на тимчасовому диску, у поточному застосунку немає експорту всієї бази, а сам деплой може очистити цей диск. Не деплой, доки не маєш окремої копії даних, які треба зберегти. Індивідуальна копія акаунта доступна авторизованому користувачу в Cloux → налаштування резервних копій, але вона не переносить акаунт і живі чати на сервер.

Локальний запуск без змінних продовжує використовувати SQLite із `CLOUX_DATA` або `./data`. Це зручно для розробки, але не є постійним сховищем на Render Free.
