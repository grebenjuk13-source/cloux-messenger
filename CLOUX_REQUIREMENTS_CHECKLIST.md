# Cloux — реєстр вимог і технічний аудит (12.10.2026)

Цей файл фіксує **реальний стан гілки** feature/cloux-secure-admin-dark-ui, а не рекламні обіцянки. 
✅ — код наявний і принаймні частково перевірений. 🟡 — зроблено не повністю або потрібні налаштування на хостингу. ❌ — не реалізовано. 
PR #18 — тестовий (draft); **бойова версія наразі не змінена**.

## Платформи, стек, розповсюдження
- ✅ Збережений оригінальний проєкт: React 19 + TypeScript + Vite, Python FastAPI, WebSocket, SQLite/PostgreSQL.
- ✅ Є існуючий Android WebView wrapper та сайт завантажень /download; macOS/Windows wrappers залишено без заміни.
- ✅ Веб-PWA: manifest, service worker, офлайн-екран, іконки 192/512, оновлення клієнта.
- 🟡 Маскабельна іконка зараз використовує існуюче квадратне зображення; потрібне окреме тестування safe zone.
- 🟡 Перевірені збірка React, серверні тести й PostgreSQL в GitHub Actions; потрібні додаткові перевірки на реальних Android Chrome, iOS Safari, Windows/macOS.
- ❌ Нові підписані APK/DMG/EXE, публікація в магазинах застосунків.
- 🟡 Готова конфігурація Render, але окремий постійний PostgreSQL сервер у реальному хостингу ще не підключений.
- 🟡 Обмежений функціональний WebRTC 1-на-1; груповий SFU, надійний TURN, native push / background calls не реалізовані.
- ❌ Повноцінні окремі Flutter/Swift/Windows нативні клієнти; наявний стек залишається PWA/WebView.

## Акаунт, приватність і сесія
- ✅ Argon2 для нових паролів (старі хеші підтримуються для сумісності).
- ✅ Сесія HttpOnly + Secure + SameSite=Lax протягом 180 днів зі ковзним продовженням; перевірка /api/me при старті зі splash.
- ✅ На стороні браузера резервний ID у localStorage; жодних секретних токенів там немає; navigator.storage.persist().
- ✅ Мережеві збої не переводять на реєстрацію; кнопка повторної перевірки.
- ✅ Серверне завершення сесії при натисканні «Вийти».
- 🟡 Ротаційний refresh token + окремий 15-хвилинний bearer access token не впроваджені; нині захищена серверна cookie-сесія.
- ✅ PostgreSQL-адаптер тестувався у CI (нові акаунти і вхід після нового підключення).
- 🟡 До релізу потрібно перенести існуючий cloux.db у Postgres без втрати користувачів/чатів/сесій; скрипт scripts/migrate_sqlite_to_postgres.py додано.
- 🟡 Укладення та аватари фізично зберігаються на диску; для масштабування потрібен S3/Supabase Storage або постійний том.
- ✅ Вхід пошта / телефон / нікнейм + пароль, валідація полів, маска +380, перевірка унікальності нікнейма, стан завантаження.
- 🟡 Підтвердження пошти кодом впроваджено для акаунта з OWNER_EMAIL; усі акаунти ще не проходять обов'язкового підтвердження адреси.
- 🟡 Серверне обмеження частоти запитів поточне однопроцесне; для кількох інстансів знадобиться Redis.
- 🟡 Не створена окрема серверна політика автоматичного видалення акаунта/даних з усіх резервних копій.

## Пріоритети перед production
1. Зробити резервну копію наявної БД, підтвердити її цілісність; **не міняти production до цього**.
2. Надати бойовому Render-сервісу постійний PostgreSQL через DATABASE_URL, за потреби мігрувати дані.
3. Налаштувати OWNER_EMAIL, SMTP_*, CLOUX_TOTP_FERNET_KEY, медіасховище.
4. Повторно пройти CI, перевірити на кількох реальних пристроях, провести захисний аудит.
5. Після перевірок об'єднати draft PR #18 із main — лише тоді Render autoDeploy оновить бойовий застосунок.
6. Пізніше окремо випустити нові APK/DMG/EXE і перевірити кожну ланку сторінки /download.

> **Конфлікт попередніх побажань:** в одній із попередніх розмов просили прибрати реєстрацію, але в останній докладній специфікації знову прямо попросили працюючу реєстрацію з перевіркою унікальності; поточна гілка відповідає новішій вимозі.
